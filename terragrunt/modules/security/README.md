# Модуль `security`

Три security group одной цепочкой:

```
интернет ──80──> ALB ──80──> приложение ──27017──> DocumentDB
```

Каждый слой принимает трафик только от предыдущего. Правила ссылаются на **другую security group**, а не на диапазон адресов: тогда правило не нужно править при масштабировании — новый инстанс попадает под него автоматически, просто потому что состоит в нужной группе.

## Входы

| Имя | Тип | По умолчанию | Описание |
|---|---|---|---|
| `name_prefix` | `string` | — | префикс имени групп, например `week3-dev` |
| `vpc_id` | `string` | — | VPC, в которой создаются группы |
| `app_port` | `number` | `80` | порт приложения на инстансе |
| `docdb_port` | `number` | `27017` | порт DocumentDB |
| `tags` | `map(string)` | `{}` | дополнительные теги |

## Выходы

`alb_security_group_id`, `app_security_group_id`, `docdb_security_group_id`.

## Что здесь неочевидно

**Правила — отдельные ресурсы, а не inline-блоки.** Провайдер поддерживает оба способа, и они несовместимы: inline-блоки `ingress`/`egress` считают себя единственным источником истины и при следующем `apply` удаляют правила, добавленные отдельными ресурсами. Модуль использует `aws_vpc_security_group_ingress_rule` и `aws_vpc_security_group_egress_rule` — по правилу на ресурс, поэтому в `plan` видно точечное изменение, а не пересоздание группы.

**`name_prefix` вместо `name`.** Имена групп уникальны в VPC, и при пересоздании Terraform попытается создать новую до удаления старой. Вместе с `create_before_destroy = true` это снимает конфликт. Отдельно: префикс `sg-` зарезервирован AWS, `terraform validate` за него ругается.

**Исходящий трафик приложения сужен.** По умолчанию разрешено всё; здесь оставлены 443 (реестр образов, Secrets Manager, SSM), 80 (репозитории пакетов) и 27017 к базе.
