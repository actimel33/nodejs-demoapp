# Модуль `launch_template`

«Рецепт инстанса»: какой образ, какой тип, какие security groups, какой user data,
под какой ролью. Отдельный юнит `app/ec2` по структуре задания.

## Почему отдельно от группы

Разделение не формальное. Шаблон отвечает на вопрос **какая машина**, группа — **сколько
их и где**. Меняются они по разным поводам и с разной частотой: правка user data или смена
образа трогают шаблон, изменение потолка нагрузки — группу. В разных состояниях `plan`
по каждому короче, а ошибка в одном не блокирует другой.

## Что создаёт

| Ресурс | Зачем |
|---|---|
| `data.aws_ssm_parameter` | свежая AMI Amazon Linux 2023 вместо захардкоженного `ami-xxxxx` |
| `aws_iam_role` + `aws_iam_instance_profile` | временные учётные данные вместо ключей доступа |
| `aws_iam_role_policy_attachment` ×2 | `AmazonSSMManagedInstanceCore` и, если база есть, чтение её секрета |
| `aws_launch_template` | сам шаблон с user data, IMDSv2 и тегами |

## Входы

| Имя | Тип | По умолчанию | Описание |
|---|---|---|---|
| `name` | `string` | — | базовое имя, например `week3-dev` |
| `region` | `string` | — | попадает в user data для вызова AWS CLI |
| `user_data_path` | `string` | — | путь к шаблону `user_data.sh` |
| `instance_type` | `string` | `t3.micro` | тип инстанса |
| `security_group_ids` | `list(string)` | — | группы для инстансов |
| `docdb_endpoint` | `string` | `""` | пустая строка — блок подключения в user data пропускается |
| `docdb_secret_arn` | `string` | `""` | ARN секрета с паролем |
| `docdb_secret_policy_arn` | `string` | `""` | пустая строка — политика не прицепляется |
| `tags` | `map(string)` | `{}` | дополнительные теги |

## Выходы

`launch_template_id` (его потребляет юнит `autoscaling`), `launch_template_name`,
`launch_template_latest_version`, `iam_role_name`, `iam_role_arn`, `iam_instance_profile_arn`.

## Три решения, которые стоит понимать

**IMDSv2 обязателен.** `http_tokens = "required"` — без токена метаданные не отдаются.
Это закрывает целый класс атак, где уязвимость типа SSRF в приложении позволяет прочитать
учётные данные роли через `169.254.169.254`.

**`create_before_destroy` на шаблоне.** Новая версия создаётся до удаления старой: группа
может ссылаться на текущую в момент применения.

**User data выполняется только при первом старте.** Правка шаблона не трогает работающие
инстансы — нужен instance refresh либо изменение desired capacity. Это регулярный источник
недоумения «поправил, применил, ничего не изменилось».
